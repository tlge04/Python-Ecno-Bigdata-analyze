# 主讲说明：这个大作业到底在做什么

这份文档只基于当前最新版本的两个文件整理：

- `最终使用tex/report/ecommerce_report.tex`
- `最终使用tex/ppt/ecommerce_beamer.tex`

它的目标不是替代报告，而是让主讲人先把整个项目的逻辑真正讲明白。看完这一份，至少应该知道：我们研究的是什么、用了什么数据、为什么这么设计、两个模型分别在解决什么问题、最后到底得出了什么结论。

## 1. 先用一句话说清楚项目

这个大作业研究的是：

**基于电商用户行为日志，分析用户从浏览到加购再到购买的转化路径，并进一步用机器学习识别高购买倾向用户和高转化加购 session。**

它不是一个单纯“画图统计”的作业，也不是一个推荐系统项目。它更准确的性质是：

1. 先做大规模行为数据处理；
2. 再做漏斗、时间、品类、品牌、价格带分析；
3. 最后做两个层次的购买预测；
4. 再把结果解释成电商运营上的转化诊断和用户分层。

所以这个项目的核心不是“模型多高级”，而是**围绕真实业务问题，把 1.77 亿条行为日志组织成一套完整的分析链路。**

## 2. 这个项目试图回答什么问题

整个项目围绕四个问题展开：

1. 三个月内，浏览、加购、购买三类行为的总体结构是什么样的？
2. 2019 年 10 月、11 月、12 月之间，行为规模和转化效率有什么差异？
3. 哪些品类、品牌、价格区间贡献了主要交易额？
4. 能不能根据用户行为特征，识别更可能购买的人或更可能转化的加购 session？

这四个问题对应了整个报告和 PPT 的骨架：

- 前半部分是描述性统计和漏斗分析；
- 后半部分是机器学习建模；
- 最后落回运营解释。

## 3. 数据是什么，为什么这个项目算“大数据分析”

数据来自 Kaggle 的电商行为日志数据集，使用了 2019 年 10 月、11 月、12 月三个月的数据。

核心字段包括：

- `event_time`：行为发生时间
- `event_type`：行为类型，主要是 `view`、`cart`、`purchase`
- `product_id`：商品 ID
- `category_code`：品类
- `brand`：品牌
- `price`：价格
- `user_id`：用户 ID
- `user_session`：会话 ID

总记录数是 **177,493,621 条**。这就是为什么它不是普通 Excel 作业。这个规模下，不能一次把数据全部读进内存，只能采用分块处理。

这里“大数据”不是说用了 Hadoop 或 Spark，而是说：

- 原始日志规模已经达到亿级；
- 必须先解决本地环境下的数据读取和聚合问题；
- 再从全量日志里提取稳定的统计结果和建模样本。

换句话说，这个项目的大数据特征主要体现在**数据规模和处理方式**，而不是分布式框架。

## 4. 整个项目的主线是什么

可以把整个项目理解成四步。

### 第一步：把原始行为日志处理成可分析的数据

原始数据是压缩 CSV 文件，而且很大。项目采用的是：

- `Pandas.read_csv(..., chunksize=1_000_000, compression="infer")`
- 每次只读取 100 万行
- 当场完成清洗、字段派生和聚合

这里做了几件关键的事：

1. 解析时间字段，提取日期、小时、月份；
2. 把 `view`、`cart`、`purchase` 转成可统计的行为标记；
3. 清洗价格、品牌、品类字段；
4. 把购买金额单独记出来；
5. 按日、按月、按小时、按品类、按品牌、按价格区间做聚合。

这一步的目标很明确：**不保留 1.77 亿条明细在内存里，而是把它们压缩成一批可解释的统计表。**

### 第二步：先把整体消费结构讲清楚

这一部分回答的是“平台整体发生了什么”。

报告里先给出了三个月的行为总量：

- 浏览：167,321,576 次
- 加购：7,350,209 次
- 购买：2,821,836 次
- 购买金额：849,329,221.91

这一层的意义是：

- 浏览量非常大，说明绝大多数行为停留在信息获取和比较阶段；
- 加购和购买明显更少，说明电商消费路径天然存在漏斗；
- 后面所有分析都围绕“为什么会在漏斗中流失”展开。

### 第三步：把用户转化路径讲清楚

报告没有只停留在事件量，而是进一步问：

**浏览之后有多少人会进入加购？加购之后又有多少人最终购买？**

这就是漏斗分析。

由于全量唯一用户去重的内存成本较高，项目对 `user_id` 做了固定取模抽样，再放大估计总体用户规模。最后得到：

- 估计浏览用户：7,853,880
- 估计加购用户：1,711,640
- 估计购买用户：1,045,680

对应比例：

- 浏览到加购：21.79%
- 浏览到购买：13.31%

这部分的业务含义是：

- 漏斗里最大的重点不是“访问量够不够”，而是“浏览到加购”和“加购到支付”这两段流失；
- 尤其是加购用户，已经表现出较强购买意向，是最值得继续研究和运营触达的人群。

### 第四步：在漏斗基础上做购买预测

项目没有停在描述统计，而是继续追问：

**我们能不能根据已有行为信号，识别谁更可能购买？**

于是做了两个模型。它们解决的不是同一个问题。

## 5. 第一个模型在做什么：用户购买倾向识别

第一个模型的样本单位是：

**用户-月份**

意思是，把一个用户在某个月内的全部行为聚合起来，变成一条样本。

标签定义是：

- 这个用户当月是否至少购买一次

特征包括：

- 总行为次数
- 浏览次数
- 加购次数
- 会话数
- 活跃天数
- 浏览商品数
- 浏览品类数
- 浏览品牌数
- 平均价格
- 最高价格

然后用逻辑回归做二分类。

这个模型的作用不是预测“下一秒下不下单”，而是识别：

**哪些用户在当前月份呈现出更强的购买倾向。**

它更像用户分层模型，而不是严格实时预测模型。

这一点一定要讲清楚。原因是：

- 特征来自当月行为；
- 标签也是当月是否购买；
- 这意味着部分特征可能已经混入购买后的行为。

所以这个模型正确的说法是：

**用户购买倾向识别模型。**

不能说成：

- “精确预测用户未来是否会购买”
- “实时购买预测”

这个模型的结果是：

- Accuracy：89.95%
- Precision：53.68%
- Recall：85.49%
- F1：0.659

它说明什么？

1. 模型很擅长把真实会购买的人尽量找出来，召回率高；
2. 但模型判成高意向的人里面，也有一部分最后没有买，所以精确率没有那么高；
3. 这类模型适合先形成营销候选池，再做二次筛选。

特征解释上，最重要的是：

- `加购次数` 是最强正向信号；
- `总行为次数` 和 `会话数` 也有正作用；
- `浏览商品数 / 品类数 / 品牌数` 为负，说明“看得太广”可能还在比较，购买意向并不稳定。

所以这个模型最重要的一句话是：

**加购行为比单纯浏览更接近真实购买意向。**

## 6. 第二个模型在做什么：购物车转化预测

这是整个项目更严谨、也更值得重点讲的部分。

前一个模型的问题是，它的时间口径不够严格。于是项目进一步把预测任务收紧到漏斗中最关键的一段：

**加购之后，用户会不会继续购买？**

这次样本单位不再是用户-月份，而是：

**`user_session`**

也就是一次会话。

入样条件是：

- 这个 session 里至少出现过一次 `cart`

观察点定义为：

- 该 session 的**首次加购时刻**

主标签定义为：

- 首次加购之后，这个 session 内是否发生任意购买

辅助标签定义为：

- 首次加购的那个商品，后续是否被购买

最关键的设计在于：

**特征只允许使用首次加购之前和首次加购当时能够看到的信息。**

这就比第一个模型更接近真实预测场景。

它使用的特征包括：

- 首次加购前事件数
- 首次加购前浏览数
- 首次加购前浏览商品数、品类数、品牌数
- 首次加购商品此前被浏览次数
- 首次加购品类此前被浏览次数
- 首次加购价格
- 加购前平均价格、最高价格
- 首次加购前 session 持续时间
- 加购小时
- 加购星期

训练测试划分也更严格：

- 2019 年 10 月和 11 月训练
- 2019 年 12 月测试

这样做的意义是：

- 避免随机切分让相似样本混到训练集和测试集里；
- 更接近“跨月份泛化”；
- 也更容易向老师解释这个模型不是简单记忆样本。

## 7. 这个购物车模型为什么在工程上更难

难点不在逻辑回归本身，而在样本构造。

因为这个任务要求知道：

1. 一个 session 的首次加购发生在什么时候；
2. 首次加购之前累积了哪些行为；
3. 首次加购之后有没有发生购买；
4. 同一个 session 可能跨多个 chunk 才读完。

所以项目没有简单 groupby，而是维护了一个轻量级 `session_state` 状态字典。

每个 session 只保存：

- 首次加购前的累计行为特征；
- 首次加购商品、品类、价格、时间；
- 加购后是否购买；
- 是否购买了首次加购商品。

也就是说，这部分工程真正解决的是：

**如何在分块扫描 1.77 亿条日志时，正确还原“首次加购前后”的 session 状态。**

这部分可以算这个项目里最有工程含量的地方之一。

## 8. 购物车模型最终得出了什么

在 1/20 用户抽样下，购物车模型这部分：

- 扫描了三个月全量 177,493,621 条原始日志；
- 抽样处理了 8,879,159 条行为；
- 构造出 216,713 个加购 session 样本；
- 主标签正样本比例为 43.99%；
- 样本构造耗时约 7.76 分钟。

12 月测试集上：

- 测试样本数：99,323
- 后续购买率：48.12%
- Precision：48.67%
- Recall：97.13%
- F1：0.648

但这个模型真正想强调的不是分类阈值，而是**排序能力**。

因为电商运营更常见的问题不是：

- “所有人买还是不买”

而是：

- “预算有限时，应该优先关注哪一批加购用户”

所以项目用了 `TopK / Lift`。

最关键结果是：

- Top 10% 高分 session 的真实购买率：60.22%
- Lift：1.25

含义是：

如果只看模型打分最高的前 10% 加购 session，这部分人真实购买率达到 60.22%，比随机挑一批人高 25% 左右。

这说明模型在排序上是有价值的。

同时，项目还做了一个重要解释边界：

**高分不等于最该发券。**

因为高分用户本来就更可能自然购买。真正适合召回的，可能是：

- 自然转化概率低；
- 但加购商品价格高；
- 一旦流失，平台损失更大。

所以报告里进一步定义了一个候选池：

- “低自然转化概率 + 高加购价格”的 session
- 共 5,545 个
- 平均首次加购价格 372.41
- 实际购买率 40.79%

这个设计很重要，因为它说明项目没有把模型分数直接误解成“发券名单”，而是进一步区分了：

- 自然转化概率
- 运营干预对象
- 因果效果

## 9. 品类、品牌、价格带分析到底在补充什么

这个项目不只是建模，也不是只盯着转化率。

品类、品牌、价格带分析回答的是：

**平台的交易结构到底是什么。**

报告里的主要发现包括：

- 手机、灯具工具、耳机、电视、冰箱、洗衣机等品类贡献主要销售额；
- Apple 和 Samsung 都重要，但结构不同；
- Apple 体现更高客单价；
- Samsung 体现更广泛的购买覆盖；
- `unknown` 品类和品牌占比不低，说明原始商品信息治理存在问题。

价格带上：

- 500--1000 价格区间销售额最高；
- 200--500 价格区间也很关键；
- 100--200 购买频次较高；
- 更高价位虽然购买次数少，但销售额贡献很大。

这部分的意义是：

1. 它解释“什么东西卖得好”；
2. 它补足了纯漏斗分析看不到的商品结构信息；
3. 它能把结论落到品类运营、价格带管理、品牌策略上。

所以品类和价格带部分不是可有可无，它负责把“转化”连接到“交易结构”。

## 10. 这个项目最后得出的总结是什么

如果把整个项目压缩成几个结论，核心就是下面五条。

### 结论一：电商行为呈现明显漏斗

- 浏览远多于加购和购买；
- 真正的优化重点不是流量本身，而是转化链路中的流失。

### 结论二：11 月和 12 月规模更大，但不能只看流量

- 促销月和年末消费确实带来规模上升；
- 但流量增加不必然等于转化效率上升；
- 所以要同时看加购率和购买率。

### 结论三：交易集中在消费电子、家电和主力价格带

- 手机、家电、消费电子是主要销售贡献品类；
- 200--1000 价格带是核心交易区间；
- 品牌之间的差异不仅体现在购买次数，也体现在客单价。

### 结论四：加购是最强购买信号

- 在用户-月份模型里，加购次数是最关键特征；
- 它比单纯浏览更接近真实购买意向。

### 结论五：首次加购前的信息可以用于 session 转化排序

- 购物车模型表明，只利用首次加购前和加购当时的信息，就能对后续购买概率做出有效排序；
- Top 10% 高分 session 的真实购买率达到 60.22%，具有实际业务价值。

## 11. 这个项目能说到什么程度，不能说到什么程度

这一部分对答辩特别重要。

### 可以说的

1. 项目处理了三个月 1.77 亿条电商行为日志。
2. 项目完整分析了浏览、加购、购买的转化结构。
3. 项目识别了主要品类、品牌和价格带。
4. 项目构建了两个层次的购买预测模型。
5. 第二个模型在购物车转化排序上有实际解释价值。

### 不要说的

1. 不要说“这是推荐系统”。
2. 不要说“模型证明发券有效”。
3. 不要说“模型预测的是未来实时下单概率”，至少第一个模型不能这么说。
4. 不要说“我们证明了促销导致购买增加”。
5. 不要把相关性结果直接说成因果关系。

原因很简单：数据里没有优惠券、曝光、库存、物流、触达这些关键字段，所以项目做的是：

- 描述统计；
- 转化诊断；
- 购买倾向识别；
- 自然转化排序。

不是因果识别。

## 13. 如果主讲人只有几分钟，应该怎么理解整个项目

可以直接记住下面这段话：

> 我们这个大作业研究的是电商用户从浏览、加购到购买的消费路径。我们用 Kaggle 三个月共 1.77 亿条行为日志，先用分块读取完成大规模清洗和聚合，再做行为结构、月度变化、转化漏斗、品类品牌和价格带分析。在此基础上，我们做了两个购买预测任务：第一个是用户-月份口径的购买倾向识别，第二个是更严格的购物车转化预测，只使用首次加购前和加购当时的信息，预测 session 后续是否购买。最后我们发现，加购是最强购买信号，购物车高分 session 的真实购买率显著高于整体均值，因此这套分析可以支持电商平台的转化诊断、用户分层和购物车召回排序。

第一句：

**这不是一个单纯画图的作业，而是一套从亿级行为日志到转化分析和购买预测的完整流程。**

第二句：

**第一个模型是购买倾向识别，第二个模型才是更接近真实触达场景的购物车转化预测。**
